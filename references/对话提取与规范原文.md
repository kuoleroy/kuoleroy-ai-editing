## 2. 剪辑相关对话时间线（用户原话 + AI 结论 + 沉淀规则）

### 阶段 0｜部署剪辑能力（1,389–1,830）

**用户原话**：「帮我把市面上可以操控剪映的技能全部部署一下，我需要你会用剪辑帮我剪视频。并且实操剪 1 条视频，你准备好了我给你发原素材。」

**AI 结论**：真正能落地的是 `pyJianYingDraft` 系（支持剪映 11.x 加密草稿），最终装的是 **pyJianYingDraft 加密版 + ffmpeg + faster-whisper**。实测能力表：

| 能力 | 组件 | 实测结果 |
|---|---|---|
| 读写加密草稿 | pyJianYingDraft + `videoeditor.dll` | 1.3 秒解密出完整 JSON，重新加密可逆 |
| 生成草稿 | `jy_tools.py build` | 测试草稿 14.17 秒 / 3 段视频 + 转场 + 变速 + 3 条字幕，自动登记进剪映列表 |
| 素材分析 | ffmpeg 6.1.1 | 46.70 秒 / 1080×1920 / 59.94fps / HEVC+AAC |
| 画面理解 | ffmpeg 抽帧拼图 | 白大褂医生坐姿口播、上方留白多、右侧书架 → 决定标题与字幕位 |
| 口播切点 | 静音检测 | 开头 4.08 秒静音、句间 0.5 秒停顿、结尾 2.2 秒静音 |
| 自动字幕 | faster-whisper small | 医学术语需词表校正（「丝状油」→「丝状疣」「米克莫特」→「咪喹莫特」） |

> **沉淀**：剪映 11.x 已取消脚本自动导出按钮，早期结论是「最终导出要人工在剪映点一次」；后续改为「导出方式不限，但工程文件必须存在」（见阶段 9）。

### 阶段 1｜第一条实操片 C5282（1,832–2,179）

**用户原话**：「c5282，是原视频，你现在可以帮我剪辑吗，郭丽.mp4，的剪辑风格你可以学习。」（附件：`郭丽.mp4`、`数字人授权.MP4`、`C5282.MP4`）

**AI 结论**：草稿 `C5282_胰腺癌科普_竖屏精剪`，51.3 秒 / 1080×1920 / 4 条轨道。复刻参考片风格：

- 顶部黄底黑字标题条全片固定；中部白字黑描边字幕（关键词红色高亮）；底部两行免责声明；
- 掐掉开头 2.6 秒、结尾 4.9 秒静音，保留口播自然停顿；
- 原片 -32.5 dB → loudnorm 标准化到 -16 LUFS、峰值 -1.3 dB；
- ASR 逐词对齐生成 19 条短字幕，医学词人工校正；
- BGM 建议 -22 dB；插图素材缺失时**明确报告缺口**，不硬凑。

**用户原话**：「后面剪出来的片子帮我单独放一个文件夹，并给我访问链接」

**交付约定（当时）**：每条片单独一个文件夹，固定四样东西——成片 mp4、效果静帧、剪辑说明、可复现方案（JSON/ASS）；剪映草稿单独留在草稿列表，两套并存。

### 阶段 2｜多轮改版与参数校准（2,183–3,224）

| 用户原话 | 落地参数 |
|---|---|
| 「字体放大 10% 放在胸口位置」「画面构图再放大 10%，上标题再放大一些」「加一些符合文案的视频素材」 | 字幕 9 → 9.9；字幕从画面 71% 上移到 60%（胸口）；上标题 10 → 11.5；插入 5 段可商用素材（2s 医患沟通 / 19s 捂腹痛 / 35s B超 / 43s 卧床 / 结尾看 CT），统一竖屏化并静音 |
| 「帮我给医生来一点磨皮美颜，来一个轻快节奏的背景音乐」 | 磨皮 70% + 粉白肤色 35%（只作用于 5 段口播，不作用于插入素材）；约 100 BPM 轻快 BGM，音量 22%（≈-13 dB），1s 淡入 / 1.5s 淡出 |
| 「磨皮美颜再增加 20%，字幕字体大小——12」 | 磨皮 84%、粉白 42%；正文字幕 9.9 → **12**；顶部标题 11.5 → 13（保持层级） |
| 「为什么我从剪映导出来字幕乱了……以后你直接给我导出视频放进文件夹。地址：<OUTPUT>」 | **根因**：字幕开启剪映「自动换行」且换行宽度设成 0.82，剪映按极窄宽度把每个字强制换行，变成一列竖排大字；ffmpeg 预览走另一套排版，未暴露问题。修正：关闭自动换行、改手动换行、标题字号回到 12。流程改为「生成剪映工程 → 直接渲染成片 → 放到 `<OUTPUT>\<片名>\<片名>.mp4`，草稿照样保留」 |

**两条重要踩坑**：
1. 预览渲染时 19–22 秒一条字幕被丢弃 → 改为「先出无字幕成片、再单独叠加字幕」两步渲染；
2. **必须用剪映导出效果验证**，不能只看 ffmpeg 预览；两条链路坐标/排版不一致会导致成片与工程画面不同。

### 阶段 3｜学习材料定级与风格提取（3,611–4,406）

**用户原话**：「我现在需要你学习剪辑思路和技巧，你是需要我把工程文件发给你学习还是视频成片发给你学习还是视频链接？要不都发给你？」

**AI 结论（材料优先级）**：

| 材料 | 能学到什么 | 价值 |
|---|---|---|
| 剪映工程（草稿文件夹） | 入/出点、删了什么、轨道结构、字幕文本+时间+字号+颜色+位置、转场/滤镜/变速/音量/BGM 位置 | ★★★★★ |
| 成片 mp4 | 最终构图、字幕样式、节奏、卡点、音效位置、BPM | ★★★☆ |
| 原素材 | 对比成片，看出「从 3 分钟里挑了哪 25 秒、为什么删」 | ★★★★（需与工程搭配） |
| 视频链接 | 平台压缩画质，只能看大概 | ★★（补充） |

**最理想组合 = 原素材 + 剪映工程 + 成片**；建议一次给 3–5 条不同风格/数据的作品。草稿路径 `%LOCALAPPDATA%\JianyingPro\User Data\Projects\com.lveditor.draft\`，**草稿加密，只能在本机读，不要打包到别的电脑还原**。

**用户原话**：「我发给你的是 3 条我们剪辑剪出来的优秀成片……每次学习，我需要你总结学习到的东西。」

**三条成片提取出的三套模板**：

- **A · 极简知识流**（0910 血糖）：单机位、黄底黑字逐句推进、26 片段平均 2.4 秒一切、BGM 占 17%、12 个音效打节奏；
- **B · 病例素材型**（0923 耳洞）：数字人 + 病例照片画中画（0.5 倍小窗左下）、45 片段平均 1.73 秒、BGM 6.5%、26 个音效；
- **C · 编号清单型**（0929 冷门科室）：01/02/03 编号推进、每个科室配全屏素材、38 片段平均 1.69 秒、17 条字幕在胸口。

**实测硬参数与旧标准对照**：

| 参数 | 实测值 | 旧标准 | 结论 |
|---|---|---|---|
| 数字人画面缩放 | **1.18**（三条一致） | 未定义 | 要加 |
| 字幕位置 | y = -0.14 ~ -0.20（胸口） | -0.20 | 对上 |
| 主字幕字号 | 10–12 | 12 | 对上 |
| 单条字幕字数 | 6.3–8.5 字 | ≤9 | 对上 |
| 字幕停留 | 2.5–3.6 秒 | 未定义 | 要加 |
| **平均片段时长** | **1.7–2.4 秒** | 3–5 秒 | **要改** |
| **BGM 音量** | **6%–19%** | 20–25% | **要改** |
| 音效数量 | 每条 12–26 个、音量 100% | 未定义 | 要加 |
| 画中画缩放 | 0.5（小窗）/ 0.8（重点） | 未定义 | 要加 |
| 免责声明 | y=-0.9、字号 5、全片常驻 | 一致 | 对上 |

> 两个最关键发现：① **BGM 只是垫底，推动节奏的是音效**；② **镜头切换密度是旧标准的两倍**。
> 风格学习要按「第 01 批 / 第 02 批」编号沉淀成团队知识库。

### 阶段 4｜参数模板与团队分工（3,641–3,783）

**用户原话**：「给我一份剪辑手册，参数模板，我让剪辑去填写。」「我现在的新媒体团队的负责人，我该如何分工，才能让 AI 剪辑可以快速逻辑进步 迭代。」

### 阶段 6｜团队四项硬要求成型（4,637–4,785）

**用户原话（四条）**：
1. 「所有的视频都需要有上标题，一直到视频结束，上标题再大 20%」
2. 「字幕太小，字幕至少还要放大 1 倍，一行不超过 11 个字，这是给中老年人看的，所有的字幕都不要有标点符号」
3. 「底部的免责声明字幕可以放大 1 倍」
4. 「你先剪 1 条 我跟你说你通过了才能剪其余剩下的。你每一个视频都需要做一个封面，字幕你提炼文案进行总结，需要精简，不要出现药品名」「每一条视频都需要匹配合适的视频素材至少要有 3 处以上，特别是开头非常重要」

**样板落地参数**：

| 要求 | 实现 |
|---|---|
| 上标题全片常驻、再大 20% | 黄底黑字「明明很困 却不想睡」，0 秒到结尾；字号 66→78，后续提到 94px（+20%） |
| 字幕放大 1 倍 | 62px → **110px** |
| 一行 ≤11 字 | 每条 ≤9 字，超长句拆成连续短句 |
| 无标点 | 全部字幕去标点 |
| 免责声明放大 1 倍 | 26px → **52px**，两行 |
| 素材 ≥3 处 | 做 4 处：开头盯天花板 / 20s 辗转难眠 / 40s 睡前看手机 / 58s 月亮 |
| 每条一个封面 | 大字主题 + 黄色两行标题 |

> **流程纪律**：先剪 1 条 → 用户验收通过 → 才批量剪其余。

### 阶段 7｜字幕与封面反复修正（4,785–5,789）

**用户原话**：「字幕对不上音频，后续的所有字幕的高度都放在胸口位置，结尾最后一句字幕没了。」

**修正**：① 从手动映射时间改为**语音识别词级时间戳**，字幕跟着口播走；② 字幕从腹部 y≈75% 上移到胸口 y≈58%；③ 最后一条字幕结束时间延长到视频结尾后 0.6 秒。
说明：为了音画对齐，字幕文本用口播原话（去标点、去口头语），不是深度改写；改写需重新对齐时间。

**封面规范（多轮反馈沉淀）**：
- 做封面**不需要工程文件，需要底图**：一张底图 + 主题即可；人物可从成片抽帧 + AI 抠图 + 白边，站姿半身照效果最好；字体用很粗黑体。
- 能力链：AI 抠图（rembg）→ 白色描边 → 背景虚化 → 超大白色主题字（如「睡眠科普」）→ 黄色两行标题 + 半透明黑条，1080×1920。
- 微调记录：两行黄字统一 80px；文字在黑条里垂直居中（上下各约 55px）；人像放大上移（宽 940→1100→1320px、y=520→300→250→140→110）；上标题合并成一行 160px、y=25→60→100→175；黑条 42% → 半透明白条 57%（不遮人像）；加右下偏移+模糊阴影；**标题文案不出现药名**。

**用户原话（断句样例，5,750–5,765）**：整夜失眠 / 却白天不困 / 这是为什么呢 …… 要求「按照这个文案断句进行换行，不要有标点符号，一行不超过 11 个字，字幕不要溢出屏幕」。

### 阶段 8｜11 条批量生产与新流程（5,804–6,519）

## 3. 公司 AI 剪辑执行规范（AI 必读 · 可直接执行）

### 3.1 六条硬性红线（违反即视为未交付）

1. **工程文件必须在**：每个成片对应一个可在剪映打开并继续精调的独立工程；导出方式不限，工程是硬性交付物。
2. **一视频一工程**：不把多条视频塞进同一个工程；不用单轨 MP4 草稿冒充工程。
3. **可编辑轨道**：原视频 / 插入素材 / 顶标题 / 字幕 / 免责声明 / BGM 尽量独立轨道；标题字幕不能烧死在画面里。
4. **不猜界面按钮**：走工程文件（plan.json → build → 注册 → read 回读），不用鼠标坐标模拟；剪映自动化失败就停止报告，不偷偷改用 FFmpeg 直出。
5. **公共盘只读**：D 盘素材库只复制、不修改；复制到自己的素材库按病症分类后再使用。
6. **版本不覆盖**：保留所有历史版本，改版用 `-一改 / -二改 / -三改`；覆盖被打开或人工改过的草稿前必须备份并征得确认。

### 3.2 输入规范（五文件夹，缺项先报告）

```
<项目目录>/
├── 封面模板/      账号过往封面（灰框/蓝灰横带为文字区）
├── 工程文件/      该账号优秀剪映工程（学习参数，按医生分别建风格卡）
├── 数字人原片/    主轨 + 声音来源
├── 素材/          与文案匹配的补充画面
├── 文案/          逐字稿（字幕唯一文本依据）
└── 输出/          成片 / 封面 / 剪辑说明 / plan.json / 字幕文件
```

缺项处理顺序：① 报告缺项 → ② 团队素材库按主题检索 → ③ 复制到个人素材库 → ④ 仍不足再去外部平台找可商用素材 → ⑤ 记录素材来源与授权。

### 3.3 标准流程（9 步）

1. **读规范 + 环境自检**：剪映版本、草稿目录、`videoeditor.dll`、便携 Python、FFmpeg、`jy_tools.py list` 读草稿成功。
2. **校验输入**：五文件夹清点，缺项报告；确认目标草稿未在剪映中打开。
3. **学风格**：解密回读参考工程，提取轨道结构、片段时长、字号/坐标、BGM 音量、音效数量，生成该医生的风格卡；不同医生分别建卡。
4. **做任务单**：写 `plan.json`（分镜、时间、字幕、素材插入点、BGM、音量、坐标）。
5. **配素材**：按逐字稿语义匹配 ≥3 处（建议 5 处），开头最重要；素材竖屏化、静音、清理平台硬字幕；复制到个人素材库。
6. **做字幕**：逐字稿 + 词级时间戳 → 去标点、单行、≤11 字、语义短句不跨画面、末句延长 0.6 秒、无时间重叠。
7. **生成工程**：`jy_tools.py build` 写剪映草稿并注册索引；成片另存（导出方式不限）。
8. **回读验收**：`jy_tools.py read` 解密回读，核对时长 / 分镜数 / 轨道 / 文本条数 / 素材路径 / 坐标 / 必备文件；再用剪辑说明 + 关键帧对照成片。
9. **交付**：工程名、完整路径、时长、轨道结构、成片路径、封面路径、验收结果、剩余风险；先交 1 条样板，用户通过后才批量。

### 3.4 参数基线（1080×1920 竖屏 / 30fps）

> **冲突处理**：早期探索值（BGM 22%–50%、片段 3–5 秒、字幕 y=75%）已被后期实测值覆盖；一律以本表为准。若某医生的参考工程参数不同，以该医生风格卡为准并在验收报告里注明偏差。

### 3.5 字幕断句与音画同步规则（可执行算法）

1. 文本**逐字来自逐字稿**，只删标点和口头语，不改写、不增删字；医学术语按词表校正（ASR 场景）。
2. 先按原文标点/语义停顿切成短句；短句 >11 字时，在语义允许处**均衡切分**，禁止机械切成一字一条。
3. 保护词表（成语、辨证名词、专有短语，如「下焦湿热」「气血亏虚」「这是很常见的气血亏虚」）**不得被切分、不得跨画面**；切素材点必须落在句子边界之后。
4. 时间来自 ASR **词级时间戳**，把逐字稿强制对齐；首句从口播实际起始出现，末句结束时间延长到视频结尾后 0.6 秒。
5. 相邻字幕事件**不得时间重叠**；每条只显示一行，关闭剪映「自动换行」（历史事故：换行宽度 0.82 导致每字竖排）。
6. 输出 `.ass` / `.srt` / 字幕 JSON 三份中的至少两份，并附机器质检结果：条数、最长行字数、标点数、重叠数、末句覆盖。

### 3.9 验收清单（逐项打勾）

**工程**：能在剪映打开；一条一工程；轨道独立（视频分镜 / 原声 / BGM / 顶标题 / 字幕 / 免责声明）；标题字幕未烧死；素材路径无大量红色缺失；时长与成片一致；顶标题 `0.84`、字幕 `-0.20`、免责 `-0.91`；`jy_tools.py read` 回读通过。

**字幕**：单行；≤11 字；无标点；无时间重叠；末句完整显示；语义短句不跨画面；首句与口播起点对齐；文本逐字来自逐字稿。

**画面**：顶标题全片常驻且不压人物；字幕在胸口不溢出屏幕；插入素材 ≥3 处且开头有；素材不重复、与原字幕不重叠；美颜只作用于医生画面。

**音频**：口播响度正常；BGM 为用户确认曲目、音量 6%–19%、有淡入淡出；音效落点合理；语速按单条修正（如 0.9 倍）。

**文件**：命名符合规范；版本未覆盖；封面/成片/工程/说明/方案齐全；公共盘未被修改。

### 3.10 排错表（历史真实故障）

| 现象 | 根因 | 修正 |
|---|---|---|
| 剪映导出后字幕变成竖排大字 | 开启自动换行且换行宽度 0.82，剪映按极窄宽度每字换行 | 关闭自动换行、改手动换行；**用剪映导出效果验收** |
| 剪映看到的标题位置和成片不一致 | ASS「顶部边距 140px」与工程 `transform_y=0.42` 坐标换算不一致 | 统一 `transform_y=0.84`；改前关闭剪映并检查后台进程 |
| 剪映里找不到昨天剪的片 | 直接用 FFmpeg 生成 MP4，没有生成剪映草稿；草稿目录在 H 盘不是 C 盘默认 | 补齐独立可编辑工程并注册索引；确认真实草稿目录 |
| 字幕对不上音频 / 慢半拍 | 按字数估时、手动映射句段时间 | 改 Whisper 词级时间戳 + 逐字稿强制对齐 |
| 最后一句字幕没了 | 末条结束时间早于视频结尾 | 延长到结尾后 0.6 秒 |
| 批量出现逐字闪字幕 | 切行算法偏向短片段 | 按标点停顿并在 11 字内均衡切分，重渲染 |
| 相邻字幕重叠 | 事件边界未去重叠 | 生成后做重叠检测并修正 |
| 关键短语跨画面 | 字幕切分与素材切换未保护专有短语 | 保护词表 + 镜头区间约束 |
| 素材自带字幕与新字幕重叠 | 引用素材含硬字幕 | 固定区域裁切 / 边缘插值清除、打码 |
| 预览渲染丢字幕 | 单步合成丢事件 | 先出无字幕成片，再单独叠加字幕 |
| 工程参数学不到 | 草稿加密、跨机打包无法还原 | 本机直接拷贝整个草稿文件夹，用 `videoeditor.dll` 解密 |
| 工程注册索引被权限拦截 | `root_meta_info.json` 在 C 盘 AppData 不可写 | 保留工程本体，靠剪映扫描 H 盘草稿目录或「导入草稿」 |
| Chrome / 桌面自动化不可用 | 沙箱多进程通道受限 | 与剪辑无关，不进入教程主线 |
