# 提示词卡（直接复制发给团队 / 智能体）

> 使用前提：目标电脑已安装 `kuoleroy-ai-editing` 技能与本机剪映工具链。
> 换机时提示词必须与工具包一起传，否则对方无法复现。

## 卡 A · 单条试剪（最常用）

```text
请先完整阅读 kuoleroy-ai-editing 技能的 SKILL.md 和 references/company-standard.md。
按公司剪辑规范处理 <项目目录>：
1. 先校验五文件夹（封面模板/工程文件/数字人原片/素材/文案），缺项先报告，不要脑补；
2. 解密回读参考工程，生成该医生的风格卡，不同医生参数分别记录；
3. 长音频先分块转写（25s 窗 / 20s 步长）再合并词级时间戳，确保 ASR 首尾覆盖全片；
   用 <SKILL_DIR>/scripts/build_subtitles.py 生成字幕，--duration 取片尾清理后的最终成片时长；
   去标点、单行、每行 ≤11 字、语义短句不跨画面、首句对齐口播实际起点、末句延长 0.6 秒、
   无时间重叠；输出 .ass/.srt/字幕 JSON 与质检结果；脚本退出码非 0 立即停止；
4. 按文案语义匹配 ≥3 处插入素材（开头最重要）；公共盘只读复制，素材入个人库并分类；
   插入素材（含视频片段）用 <SKILL_DIR>/scripts/select_inserts.py：--scan 出候选（大素材库全库只扫文件名，可加 --include 主题词；只对入选片段 ffprobe）→ 我确认语义/源入出点/授权 → --apply 写入任务单并质检 → --verify 复核；
   视频片段要真正进工程：用 <SKILL_DIR>/scripts/build_insert_draft.py 先默认 dry-run 出构建计划（含相邻帧动检），我确认后 --build --drafts-dir <剪映草稿目录> --draft-name <新工程名>；同名工程拒绝覆盖，门禁不过退出码 2；剪映里能否打开必须我人工验证一次；
   视频片段要 volume=0、带源入出点留 0.2s 余量、1.7-2.4s；脚本退出码 2 立即停止；
5. 顶标题全片常驻、黄色圆角底、不出现药名；封面 1080×1920，文字放进灰框并垂直居中；
   优先沿用账号封面模板换文案，无模板才用 assets/封面生成提示词.md 出底图；
   人像必须来自本人授权真人照片/成片抽帧（禁止 AI 凭空生成医生脸），中文文案后期叠加且逐字取自 plan.json cover 字段；
6. BGM 先给 4–5 首候选等我确认，不要自己定；
7. 生成一条独立剪映可编辑工程（视频分镜/原声/BGM/顶标题/字幕/免责声明各自独立轨道，
   顶标题 transform_y=0.84、字幕 -0.20、免责 -0.91），并另存可预览成片；
8. 用 jy_tools.py read 回读验收 + <SKILL_DIR>/scripts/qc_delivery.py 生成验收报告；
   验收脚本存在 FAIL 会返回退出码 1，不得略过、不得加 --no-strict 强行放行。
先只剪 1 条样板，交工程名、路径、时长、轨道结构、成片、封面和验收结果。
我确认通过后，才按同一标准批量处理其余视频。
任何一步失败就停止并报告，不要改用 FFmpeg 直出 MP4 冒充工程。
```

## 卡 B · 批量生产

```text
按已验收样板的参数，批量处理 <目录> 下序号 X–Y 的视频。
一条视频一个独立剪映工程，工程与成片一一对应、分目录保存；
保留全部旧版本，改版用 -一改/-二改/-三改，不覆盖已打开或人工修改过的草稿。
逐条做工程回读验收（时长/轨道/文本条数/素材路径/坐标）与字幕质检；
字幕或验收脚本退出码非 0 立即停止该条，不进入下一条；
输出汇总表：工程名、完整路径、时长、轨道结构、成片路径、封面路径、验收结果、剩余风险。
任何加密写入、注册、回读或字幕质检失败，立即停止并报告具体错误与需要补充的文件。
```

## 卡 C · 单条修片

```text
只修改 <片名> 的以下问题：<逐条列出修改点>。
生成新的 -N改 版本，保留所有旧版；不要改动其他视频。
若涉及语速/时间轴变化，必须同步重建字幕时间轴并重新做音画对齐。
改完回读工程、做字幕质检、抽关键帧对照成片，报告修改前后对照。
```

## 卡 D · 学习优秀成片 / 更新参数库

```text
我给你 <N> 条优秀成片和对应剪映工程、原素材。请按第 NN 批编号学习：
逐条提取轨道结构、平均片段时长、开头 3 秒结构、字幕字号/位置/断句、BGM 音量、
音效数量、变速、转场、免责声明位置，输出参数对照表（实测值 vs 当前公司基线）。
明确列出「需要修改的基线项」和「因素材缺失无法确认的项」。
每次学习都要总结学到了什么；参数更新前先给我确认，通过后再写入 company-standard.md 和风格卡。
同类修改出现 3 次以上，按三次法则升级为团队参数。
```

## 卡 E · 新电脑部署

```text
你是部署执行代理。请在当前 Windows 电脑上部署 AI 剪辑能力。
我已提供 kuoleroy-ai-editing 技能包、jianying-skill、便携 Python、FFmpeg 和剪映技能文件包。
请先完整读取 SKILL.md 与 references/environment.md，不能只读摘要，也不能根据剪映按钮位置猜测操作方式。

检查并部署：Windows 10/11、最新版剪映、本机 videoeditor.dll、Python 3.11、FFmpeg、
pyJianYingDraft 及 jy_tools.py 依赖。优先复用我提供的便携组件，不重复下载或覆盖已有版本。

部署必须实测：运行 Python 与 FFmpeg 版本检查；jy_tools.py list 读取本机剪映草稿；
probe 检查一个视频素材；生成一个最小测试工程；再用 jy_tools.py read 解密回读，
确认工程有真实视频轨、文本和音频并已注册到剪映首页。

最后输出：已安装组件与版本、剪映版本与草稿目录、videoeditor.dll 路径、
Python 和 FFmpeg 路径、list 验证结果、测试工程名称与绝对路径、剩余风险或缺失项。
任何依赖安装失败、草稿写入失败、加密回读失败或素材缺失，都停止操作并报告。
```

## 卡 F · 交付验收复核

```text
请复核 <项目目录> 的交付物是否合格，不要重新剪片。
按 references/company-standard.md 第 9、10 节逐项检查：
每个成片是否有对应独立可编辑工程、轨道是否独立、标题字幕是否未烧死、
字幕是否单行≤11字无标点无重叠且末句完整、素材是否≥3处且公共盘未被修改、
命名与版本是否合规、封面与说明/任务单/验收报告是否齐全。
运行 <SKILL_DIR>/scripts/qc_delivery.py --project <项目目录> --drafts <剪映草稿目录> 输出验收报告，
只列出不合格项、根因与需要补的文件（默认严格，FAIL 返回退出码 1；不要加 --no-strict）。
```

## 卡 G · 团队统一口径（发给全员的短版）

```text
以后所有 AI 剪辑统一按 kuoleroy-ai-editing 技能执行，六条红线：
工程文件必须在；一条视频一个工程；轨道可编辑、字幕标题不烧死；
不猜剪映按钮、不用 FFmpeg 直出 MP4 代替工程；公共盘只读复制；
改版保留旧版（-一改/-二改/-三改）。
字幕：逐字稿 + 词级时间戳、单行 ≤11 字、无标点、语义短句不跨画面。
先剪 1 条样板给我验收，通过后才批量；BGM 先给候选等我选。
每条交付：独立工程 + 成片 + 封面 + 任务单 + 字幕 + 剪辑说明 + 验收报告。
封面：沿用账号模板优先；人像用本人授权真人素材，禁止 AI 凭空造医生脸；中文文案后期叠加、不出现药名与疗效承诺。
```
