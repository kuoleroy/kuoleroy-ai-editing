# 安装与分发说明（全员适用）

## 1. 这个技能包是什么

`kuoleroy-ai-editing` 是公司短视频部统一的 AI 剪辑规范包。它把已验证的剪辑流程、参数基线、字幕规则、排错经验和交付验收固化下来，让任何一位同事用 WorkBuddy / Codex 都能按同一标准剪出「可继续精调的工程文件」，而不是只有一堆无法修改的 MP4。

包含：

```
kuoleroy-ai-editing/
├── SKILL.md                    智能体执行入口（先读这个）
├── references/
│   ├── company-standard.md     参数基线 / 输入 / 命名 / 验收（执行前必读）
│   ├── pitfalls.md             历史故障与根因
│   ├── environment.md          工具链、新机部署、跨软件适配
│   ├── prompt-cards.md         可直接复制的提示词卡
│   └── 对话提取与规范原文.md    完整对话时间线、参数出处与证据行号
├── scripts/                    核心脚本纯 Python 3 标准库，任何机器可跑
│   ├── init_project.py         五文件夹初始化 / 缺项检查
│   ├── build_subtitles.py      逐字稿断句 + 强制对齐 + 质检（v1.1）
│   ├── style_profile.py        从明文剪映草稿提取风格卡
│   ├── qc_delivery.py          交付验收并生成报告（默认严格退出）
│   ├── select_inserts.py       插入素材选点（全库文件名直扫 + 入选才 ffprobe）、授权与质检（v1.4）
│   ├── build_insert_draft.py   把插入点写成剪映草稿工程（v1.4，--build 需 pyJianYingDraft）
│   └── selftest.py             回归自测 20 项
└── assets/
    ├── 剪辑任务单模板.json      plan.json 标准模板
    ├── 交付验收清单.md          人工验收勾选项
    ├── 封面生成提示词.md        封面底图提示词（v1.2，含三条护栏，公开版已脱敏）
    ├── 保护词表-医疗示例.txt    字幕断句保护词
    ├── 示例逐字稿.txt           自测素材
    └── 示例词级时间戳.json       自测素材
```

## 2. 安装位置

| 客户端 | 安装路径 | 生效范围 |
|---|---|---|
| WorkBuddy | `%USERPROFILE%\.workbuddy\skills\kuoleroy-ai-editing\` | 当前用户所有项目 |
| WorkBuddy（团队共享） | `<项目>\.workbuddy\skills\kuoleroy-ai-editing\` | 该项目所有成员 |
| Codex CLI | `%USERPROFILE%\.codex\skills\kuoleroy-ai-editing\` 或项目 `.codex\skills\` | 对应会话 |

把整个 `kuoleroy-ai-editing` 文件夹原样复制过去即可。字幕、选点、验收、自测脚本**无需任何 pip 依赖**；只有 `build_insert_draft.py --build`（把视频片段写进剪映工程）需要 `pyJianYingDraft`，动检/自适应缩放用到可选 FFmpeg。分发的 zip 包解压后目录名必须保持 `kuoleroy-ai-editing`（与 SKILL.md 里的 `name` 一致）。

## 3. 三分钟自测（v1.4）

**推荐一键自测**（20 项回归，纯标准库、任意工作目录可跑）：

```bash
python <SKILL_DIR>/scripts/selftest.py
```

全部输出 `PASS`、结论 `20/20 通过` 且退出码 0，才算技能包可用；升级分发前必跑。

也可手工跑三步（`<SKILL_DIR>` 用绝对路径，**不要依赖当前工作目录**）：

```bash
python <SKILL_DIR>/scripts/init_project.py ./selftest --doctor 示例甲 --topic 失眠
python <SKILL_DIR>/scripts/build_subtitles.py --script <SKILL_DIR>/assets/示例逐字稿.txt --out ./selftest/输出/字幕 --words <SKILL_DIR>/assets/示例词级时间戳.json --protect <SKILL_DIR>/assets/保护词表-医疗示例.txt --duration 42.60
python <SKILL_DIR>/scripts/qc_delivery.py --project ./selftest
```

预期：

- 第一条：生成五文件夹 + `输出/剪辑任务单.json`，输出含 `skill_dir`；
- 第二条：生成 `字幕.json` / `.srt` / `.ass` / `字幕_质检.json`，`ok: true`、`pass: true`、`alignment_status: exact`、`text_verbatim: true`、`tail_reaches_end: true`，退出码 0。`--duration` 必填，取片尾清理后的最终成片时长；
- 第三条：生成 `输出/验收报告.md`；自测环境因缺成片、封面、工程而报 FAIL 并**返回退出码 1**（严格模式，属预期）。排查时可加 `--no-strict` 返回 0，正式交付禁止使用。

若第二条 `failed_checks` 含 `time_coverage`：ASR 时间戳未覆盖全片，长音频需按 25s 窗 / 20s 步长分块转写再合并；含 `no_interpolation`：先看质检 JSON 的 `alignment.differences`，人工确认后加 `--allow-interpolation N` 显式放行并写进剪辑说明。

## 4. 每台剪辑电脑还要装什么

技能包本身只负责「规范 + 质检 + 插入片段工程构建」。要真正生成完整剪映工程，还需要本机剪映工具链（详见 `references/environment.md`）：

- 剪映 JianyingPro 11.x（提供 `videoeditor.dll`）
- 便携 Python 3.11 + `pyJianYingDraft`（`build_insert_draft.py --build` 直接依赖；`python -c "import pyJianYingDraft"` 自检）
- FFmpeg 6.x（相邻帧动检、cover 缩放计算、可选 ffprobe 探测）
- `jianying-skill` / `jy_tools.py`（完整六/七轨工程、加密写入与首页注册）
- 可选：faster-whisper（词级时间戳）、rembg / 图像生成（封面，提示词见 `assets/封面生成提示词.md`，仅作无模板时兜底）

**v1.4 实测环境**：Python 3.13 + `pyJianYingDraft`（`DraftFolder` / `ScriptFile` / `VideoSegment` 新版 API）+ FFmpeg/ffprobe。剪映 11.7 现存工程的 `draft_content.json` 与 `draft_meta_info.json` 均为**加密**内容，而 `pyJianYingDraft` 写出的是明文工程——首次换机必须按 `输出/工程构建/剪映打开验证.md` 人工打开确认一次，不能只看脚本返回 `ok:true` 就当交付完成。

**换机部署时，提示词必须和工具包一起传**，只发提示词对方复现不了。部署后必须实测 `jy_tools.py list` → `probe` → 生成最小测试工程 → `read` 回读 → 剪映首页可见。

## 5. 第一次正式使用

1. 按五文件夹准备材料（封面模板 / 工程文件 / 数字人原片 / 素材 / 文案）。
2. 复制 `references/prompt-cards.md` 的「卡 A · 单条试剪」发给智能体。
3. 先只剪 1 条样板，按 `assets/交付验收清单.md` 人工打开剪映核对。
4. 用户确认通过后，用「卡 B · 批量生产」处理其余视频。
5. 每次交付必须附上 `qc_delivery.py` 生成的验收报告。

## 6. 升级与迭代

**v1.4 变更（视频片段自动进剪映工程 · 阶段 2）**：新增 `scripts/build_insert_draft.py`——复用 `select_inserts.py` 全部门禁，用 `pyJianYingDraft` 把每条插入点写成 `VideoSegment(source_timerange, volume=0)` 并挂到独立「插入素材」轨；支持可选主视频轨与 SRT 字幕轨、cover 自适应缩放、相邻帧 framemd5 动检（防「静帧冒充视频片段」）、明文回读审计、同名工程拒绝覆盖；默认 dry-run，`--build` 才写工程。`select_inserts.py` 改为**全库只扫文件名 + 只对入选素材 ffprobe 的两阶段扫描**（905 个素材实测 19ms 建索引 + 5 个探测 193ms，原逐文件探测约 33s），新增 `--include` 主题关键词、改进语义打分为 2-gram + 停用字过滤。`selftest.py` 16 → 20 项（新增 dry-run 计划、门禁拦截、版本不覆盖、缺草稿目录报错），并修掉「构建期报错会崩而不是返回退出码 2」的缺陷。**六条红线、`company-standard.md` 参数基线、规范层均未改动；剪映 11.7 明文/加密工程兼容性与阶段 0 规范层仍待批准验证。**

**v1.3 变更（插入素材能力 · 阶段 1）**：新增 `scripts/select_inserts.py`（`--scan` / `--apply` / `--verify`，纯标准库、ffprobe 可选），把 `plan.json` 的 `assets.insert_points` 升级为带 `insert_points_schema` 说明的对象数组契约；硬约束含 ≥3 处、开头 3s 有插入、1.7–2.4s、源片段 ≥0.2s 余量、`volume=0`、`license_status=approved`、句边界切点、零重叠、不重复，失败退出码 2；**候选授权默认 unknown 必 FAIL，强制人工确认**。AI 只给候选、不自动定稿，脚本不写剪映工程、不渲染成片。`selftest.py` 11 → 16 项；`SKILL.md` 步骤 4 / 脚本表、验收清单 C 节、提示词卡 A 同步。**六条红线、`company-standard.md` 参数基线、既有脚本逻辑均未改动；阶段 0 规范层（7 轨 / 回读双路径 / 安全区 / 帧率）仍待批准。**

**v1.2 变更（封面能力，纯增量）**：新增 `assets/封面生成提示词.md`（由 57 张真实封面样本反推，按团队规范改造）；`SKILL.md` 步骤 4 增补封面优先级与三条护栏；`plan.json` 的 `cover` 增补底图来源、授权、风格变体、合规复核字段；`assets/交付验收清单.md` E 节增补 6 项人工检查；提示词卡 A / G 同步。**未改动六条红线、参数基线、任何脚本与质检门禁。** 封面提示词是文本资产，不自动出图；文件含样本归纳结论，公开版已完成脱敏处理。

**v1.1 变更（P0 修复）**：字幕脚本改为逐字稿/ASR 字符级强制对齐、禁止时间轴外推、增加 ASR 覆盖与匹配率门禁、`--duration` 必填、断句不跨标点、单字行判不合格；`qc_delivery.py` 默认严格退出、兼容剪映 11.7 的 `draft_content.json`、支持 `acceptance.deferred_items`；所有命令统一 `<SKILL_DIR>/scripts/`；新增 `selftest.py`（11 项回归）。**六条红线与参数基线未改动。**

- 同类修改出现 3 次以上（三次法则），由 AI 剪辑运营更新 `references/company-standard.md` 的参数基线，并把新参数写进任务单模板。
- 每批优秀成片学习结果按「第 01 批 / 第 02 批」编号，风格卡 JSON 随项目归档。
- 新增故障写入 `references/pitfalls.md`（现象 / 根因 / 修正 / 验证方法）。
- 修改本技能包后重新打包 zip 分发，注明版本号与变更点；不要直接改各人电脑上的副本。

## 7. 适用范围说明

规范层（输入、字幕、参数、命名、验收、红线）**与剪辑软件无关**。当前工程落地实现以剪映为主；若公司改用爱剪辑或其他剪辑器，按 `references/environment.md` 第 6 节替换「读工程 / 写工程 / 注册可见 / 回读验收」四类适配能力即可，不要改成「猜按钮」或「直接渲染 MP4 代替工程」。
