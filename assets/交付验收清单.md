# 交付验收清单（人工勾选 + 脚本复核）

> 脚本复核：`python <SKILL_DIR>/scripts/qc_delivery.py --project <项目目录> --drafts <剪映草稿目录>`（v1.1 起默认严格，存在 FAIL 返回退出码 1；旧 `--strict` 仍兼容，`--no-strict` 仅供排查）
> 脚本无法替代剪映内的人工打开确认，标「人工」的项目必须逐条看。

## A. 工程（硬性交付物）

- [ ] 每个成片有对应的独立剪映工程，一条一工程
- [ ] 工程在剪映首页可见、能正常打开（人工）
- [ ] 工程名与成片名一一对应
- [ ] 轨道独立：视频分镜 / 原声 / BGM / 顶标题 / 字幕 / 免责声明
- [ ] 顶标题、字幕**没有烧死在画面里**（人工：试着改一个字）
- [ ] 打开工程无大量红色缺失素材（人工）
- [ ] `jy_tools.py read` 解密回读通过，核对时长、分镜数、文本条数、素材路径
- [ ] 坐标：顶标题 `0.84`、字幕 `-0.20`、免责声明 `≈-0.91`
- [ ] 工程目录含 `draft_info.json`/`draft_content.json`、`draft_meta_info.json`、`draft_cover.jpg`
- [ ] 覆盖旧工程前已备份，且未在剪映打开状态下覆盖

## B. 字幕

- [ ] 文本逐字来自逐字稿，无改写增删
- [ ] 单行显示，每行 ≤11 字
- [ ] 无标点
- [ ] 相邻事件无时间重叠
- [ ] 首句与口播起点对齐（无慢半拍）
- [ ] 末句完整显示（延长 0.6 秒）
- [ ] 语义短句 / 成语 / 辨证名词不跨画面
- [ ] 关闭剪映「自动换行」
- [ ] 交付 `.ass` / `.srt` / 字幕 JSON + 字幕质检结果
- [ ] 医学术语已按词表校正
- [ ] 质检 JSON 的 `text_verbatim` / `tail_reaches_end` / `time_coverage` 均为 PASS，`failed_checks` 为空、无未复核插值

## C. 画面与素材

- [ ] 顶标题全片常驻、不压人物、文案不出现药名
- [ ] 字幕在胸口位置、不溢出屏幕
- [ ] 插入素材 ≥3 处（建议 5 处），开头有素材
- [ ] `select_inserts.py --verify` 通过：`输出/insert_points_质检.json` 的 `ok=true`、`failed_checks` 为空
- [ ] 视频片段确为动态视频：构建计划的 `motion.status=moving`（相邻两帧 framemd5 不同），不是抽帧静图
- [ ] `build_insert_draft.py` 构建报告 `audit.ok=true`：插入素材轨独立、`all_muted=true`、`all_have_source_timerange=true`、素材 `type=video`
- [ ] 工程按 `输出/工程构建/剪映打开验证.md` 在剪映实际打开确认：片段会动、已静音、未盖住字幕与顶标题、素材路径无红色缺失
- [ ] 同名工程未被覆盖；明文 `draft_content.json` 已留备份到 `输出/工程构建/`
- [ ] 插入点已人工确认语义、源入出点、授权状态；`license_status` 非 approved 的素材未使用
- [ ] 视频片段 `volume=0`、带源入出点且留 ≥0.2s 余量、单条 1.7–2.4s（图片无源入出点）
- [ ] 同轨零重叠、素材不重复、切点落在字幕句边界、开头 3s 内有插入
- [ ] 相邻帧比对确认插入的是**动态视频而非静帧**（人工；脚本化属 v1.3 阶段 3）
- [ ] 源帧率与工程 30fps 的偏差已登记 `acceptance.deferred_items` 或确认一致
- [ ] 素材与文案语义匹配、不重复使用
- [ ] 插入素材竖屏化、静音、无平台硬字幕遮挡
- [ ] 美颜只作用于医生口播画面
- [ ] 公共素材盘只复制、未修改（人工确认）
- [ ] 素材来源清单已记录

## D. 音频

- [ ] 口播响度正常（-16 LUFS 基准）
- [ ] BGM 是用户试听确认的曲目
- [ ] BGM 音量 6%–19%，有淡入淡出
- [ ] 音效落点合理
- [ ] 单条语速按反馈修正（如 0.9 倍），时间轴已同步重建

## E. 封面

> 底图生成提示词见 `assets/封面生成提示词.md`（v1.2，含三条硬性护栏）。以下标「人工」的项目脚本无法替代。

- [ ] 1080×1920（沿用账号 2:3 模板时按账号规格，并在验收报告注明偏差）
- [ ] 优先级正确：沿用账号封面模板 → 成片抽帧抠图 → 无模板才用提示词出底图
- [ ] 人像来自本人授权真人照片 / 成片抽帧，**非文生图凭空生成的陌生医生脸**（人工）
- [ ] `cover.portrait_source` / `cover.portrait_license` 已填写，肖像与标识授权可追溯
- [ ] 主题文案精简、不出现药名
- [ ] 文案无「根治/包好/特效/治愈」等绝对化用语、无剂量与疗效建议（人工）
- [ ] 中文文案为后期叠加，逐字对应 `plan.json` 的 `cover` 字段，无错字、乱码、变形（人工）
- [ ] 沿用账号封面模板（灰框/蓝灰横带），风格变体与该医生风格卡一致
- [ ] 两行标题同字号，在框内垂直居中
- [ ] 人像居中、放大上移，横条不遮人像
- [ ] 独立交付封面 JPG 与工程内 `draft_cover.jpg` 均存在

## F. 文件与版本

- [ ] 成片命名 `日期-XXX医生——主题`（主题 ≤6 字）
- [ ] 封面命名 `医生名-主题`
- [ ] 改版用 `-一改/-二改/-三改`，旧版全部保留
- [ ] 成片 / 工程 / 封面 / 任务单 / 字幕 / 剪辑说明 / 验收报告齐全
- [ ] 成片与工程分开保存

## G. 流程纪律

- [ ] 先交 1 条样板，用户确认通过后才批量
- [ ] 样板待补项已登记 `acceptance.deferred_items`，批量前已清零
- [ ] BGM 先给候选，用户选定后才渲染
- [ ] 不同医生分别建风格卡，未一套模板套全部
- [ ] 本次修改若属同类第 3 次，已按「三次法则」更新团队参数
- [ ] 验收报告已附剩余风险与待确认项
